# EquityLens V5 — Feature Roadmap (What Professional Platforms Do, and What's Worth Building Next)

Status: research/reference, not started. This surveys what Bloomberg Terminal, BlackRock Aladdin, Morningstar X-Ray, Portfolio Visualizer, Koyfin, Simply Wall St, Seeking Alpha, and the robo-advisor tax-management platforms (Betterment, Envestnet, Altruist) actually ship for risk tracking and portfolio management, then maps each capability against what EquityLens already has, what's a genuine next-version candidate, and what needs data you don't currently have access to. Organized by priority tier at the end so a future session can pick straight from it.

## What the category actually looks like today

Three distinct tiers exist in the market, and it's worth being clear about which one EquityLens is competing with. **Institutional** (Aladdin, Barra): proprietary multi-factor risk models decomposing exposure across 2,000+ factors, daily stress tests, portfolio-level "what-if" optimization — licensed data, seven-figure contracts, not a realistic bar for a demo project. **Prosumer/advisor** (Morningstar X-Ray, Koyfin, Portfolio Visualizer, YCharts): style-box factor analysis, backtesting, Monte Carlo retirement planning, correlation/concentration dashboards — largely buildable with free data plus real quant work, which is the right comparison set for EquityLens. **Retail rating apps** (Simply Wall St, Seeking Alpha): a single blended score or "snowflake" distilling value/growth/quality/momentum into something scannable — good UX pattern, cheap to build once you already compute the underlying percentiles (which EquityLens does).

## Feature-by-feature: what exists elsewhere, what EquityLens has, what's missing

**Factor exposure / style analysis.** Morningstar's Style Box plots every holding on a size (large/mid/small) × style (value/blend/growth) grid and rolls it up to a portfolio-level box — the single most-copied visualization in the category. Portfolio Visualizer runs actual Fama-French three-factor (and Carhart four-factor) regressions against a fund's historical returns to quantify market/size/value/momentum betas. EquityLens today computes P/E percentile and a momentum score per stock but never rolls them into a portfolio-level style view, and has no factor regression at all. A style box is buildable now — size from market cap (already fetched), value/growth from a P/E-relative-to-sector or P/E-percentile tilt (already computed) — no new data needed, just a new aggregation and a 2D scatter/grid chart. A real Fama-French regression needs the actual factor return series (SMB, HML, MOM), which isn't in Alpha Vantage but is freely published by Ken French's data library at Dartmouth (CSV download, no API key, updated monthly) — a one-time or periodic manual/scripted pull rather than a live API integration.

**Stress testing / scenario analysis.** The universal best practice across every institutional source: apply defined historical or hypothetical shocks to current positions rather than relying only on the normal-distribution assumption behind parametric VaR (which EquityLens already discloses as a limitation). EquityLens has the exact building block needed — per-stock beta against the benchmark — so a "what if the market drops 20% like March 2020" or "what if rates shock +200bp" scenario is a direct extension: shock the benchmark/factor return, propagate through existing betas, report portfolio P&L. This is genuinely the highest-value, lowest-cost addition on this whole list — it uses data you already have, no new API calls, and it's the single feature every professional source flagged as core practice that EquityLens is currently missing entirely.

**Concentration & correlation risk.** EquityLens already computes HHI, Effective N, and a full correlation matrix — ahead of a lot of retail tools here. What's missing relative to the dashboards researched: explicit threshold-based flags (e.g., "XLE + SHEL + XOM are 61% of NAV and correlate at 0.7+ — this isn't diversification, it's one energy bet"), and correlation *clustering* (grouping positions that move together rather than just showing the raw matrix and leaving the user to eyeball it). Both are pure computation on data already in hand.

**Drawdown & tail risk.** Max drawdown, Sortino (downside deviation), and parametric CVaR are already built. What professional dashboards add on top: a drawdown *chart over time* (not just the single worst number), and empirical (historical-simulation) VaR/CVaR as a complement to the parametric version — sort actual historical returns and take the empirical 5th percentile, which doesn't assume normality and is a natural pairing with the scenario-stress feature above.

**Rebalancing.** This is a real gap. Every advisor-facing platform researched treats target-weight drift tracking as core, not optional: set a target allocation, track live drift from target, flag when a position exceeds its band, suggest the trade to get back in line. EquityLens today only supports ad-hoc share adjustments with no target reference point at all — there's nothing to "drift" from. Straightforward to build: add a `targetWeight` field per position (or per sector), compute drift = current weight − target, flag/sort by |drift|, suggest buy/sell dollar amounts to close the gap. No new data needed.

**Tax awareness.** Betterment/Altruist/Envestnet all center tax-loss harvesting and wash-sale detection as flagship features. EquityLens now has `avgCost` per position (from the Excel import work), which unlocks realized/unrealized gain-loss tracking for free — that's the prerequisite that wasn't there before and is worth surfacing now (unrealized P&L per position, portfolio-level embedded gains). True tax-loss-harvesting *suggestions* (flag a loss position and propose a correlated substitute to swap into) is a reasonable next step once that's in. Wash-sale detection needs actual transaction history (buy/sell dates and lots), which the current data model doesn't track — that's a bigger lift (new `transactions` log, not just `positions`) and should wait until there's real demand for it.

**Dividend / income tracking.** Not currently a first-class view anywhere in EquityLens despite `divYield` being pulled per stock. A portfolio-level annualized income projection (Σ shares × price × yield) and a dividend calendar are cheap wins with data already fetched. Alpha Vantage's `DIVIDENDS` endpoint (in your connected MCP, unused) would upgrade this from "current yield" to real historical dividend growth/consistency — the same category Simply Safe Dividends and Seeking Alpha's Dividend Grades compete in — at the cost of one extra call per ticker.

**Composite rating / score.** Simply Wall St's "Snowflake" and Seeking Alpha's Quant Rating both do the same thing conceptually: blend several already-computed dimensions (value, growth, quality, momentum) into one visual score so a user doesn't have to mentally average eight numbers. EquityLens already computes P/E percentile, momentum score, ROE, revenue growth — the inputs exist. Building a 4-5-axis radar chart or a single blended 0–100 "EquityLens Score" per stock is genuinely close to zero marginal data cost and is a strong differentiator for a portfolio-piece demo, since it shows you can turn raw metrics into a decision-support signal rather than just a data table.

**News & sentiment.** Increasingly standard (Seeking Alpha alerts, AI-driven sentiment gauges next to holdings). Alpha Vantage's `NEWS_SENTIMENT` endpoint is already available in your connected MCP and unused — costs one extra call per ticker for a real sentiment score plus headline feed, cheaper than most of what's on this list to add credibly.

**Backtesting.** Portfolio Visualizer's core differentiator, and a real gap in EquityLens today. A simplified version — "if you'd held this exact weight allocation since date X, what would total return/vol/Sharpe/max-drawdown have looked like" — is buildable on `PRICES_FULL`, but the free-tier `TIME_SERIES_DAILY?outputsize=compact` only returns ~100 sessions (already a documented README limitation); real backtesting needs `outputsize=full`, which is a bigger, slower response and would need its own budget treatment in the refresh job. Worth scoping as static-weight-only (no historical rebalancing) for v1 — a real disclosed simplification, consistent with how VaR/P-E-percentile approximations are already handled.

**Monte Carlo simulation.** Used everywhere for both portfolio terminal-value projection and retirement/goal planning (Portfolio Visualizer, Boldin, most robo-advisors). Purely computational — simulate the portfolio forward using its own computed mean/vol via geometric Brownian motion, run a few thousand paths, show a percentile fan chart of terminal value. Zero new API calls, real quant substance, high visual payoff — probably the best "wow" feature per unit of build effort on this entire list.

**Options hedging overlays.** Covered calls / protective puts / collars layered on existing holdings are standard at the advisor tier (BlackRock SpiderRock, etc.). This is really the same ground as the Derivatives track already scoped in `equitylens-bonds-derivatives-plan.md` — don't duplicate; once options pricing/Greeks exist there, a "hedge this position" suggestion becomes a natural portfolio-view feature that consumes that work rather than a separate build.

**Multi-currency / global.** Spot FX conversion for non-USD positions already exists from the Excel import work. What professional platforms add on top: historical FX-adjusted returns (so a EUR position's risk metrics reflect currency volatility too, not just today's conversion) — currently disclosed as a known simplification, worth revisiting once there's an actual multi-currency portfolio being tested against it.

**Liquidity risk.** Barely covered anywhere in retail tools, more of an institutional concern, but genuinely trivial to add: `avgVolume` is already fetched per ticker, so a "days to liquidate" metric (position shares ÷ average daily volume) is a one-line calculation that flags concentrated positions in thin names — cheap, real, differentiated since almost nothing at the retail tier surfaces this.

**Alerts / notifications.** Every platform researched treats this as core (price alerts, rebalancing-drift alerts, valuation-percentile alerts). EquityLens is a local single-user app with no backend or push infrastructure, so "alerts" here realistically means in-app flags computed and surfaced the next time the app is opened (e.g., a small badge count in the nav: "3 positions have drifted past their rebalancing band," "NVDA crossed into 'expensive vs. history'") rather than actual push notifications — a reasonable, honest scope given the architecture.

## Priority tiers for the next version

**Tier 1 — build first (high value, zero new data cost, uses what's already fetched):** historical scenario stress testing off existing betas, target-weight rebalancing with drift tracking and trade suggestions, concentration/correlation threshold alerts, portfolio-level style box (size × value tilt), composite per-stock score (blend of already-computed percentiles), Monte Carlo terminal-value simulation, realized/unrealized P&L now that cost basis exists, liquidity ("days to liquidate") flag, empirical (historical) VaR/CVaR alongside the existing parametric version.

**Tier 2 — valuable, needs one more (already-available) data source per ticker:** dividend income projection + calendar via `DIVIDENDS`, news sentiment via `NEWS_SENTIMENT`, a real Fama-French factor regression using the free Ken French data library, simplified static-weight backtesting via `outputsize=full`.

**Tier 3 — stretch, needs new infrastructure or paid/third-party data:** wash-sale-aware tax-loss harvesting (needs a transaction log, not just current positions — a real data-model change), true third-party ESG scores (MSCI/Sustainalytics-grade data is paid, not available via Alpha Vantage free tier), options hedging overlays (defer to the already-scoped Derivatives track), historical FX-adjusted (not just spot-converted) multi-currency returns, institutional-grade multi-factor risk models in the Barra sense (licensed data, not a realistic free-tier target — the DIY style-box + Fama-French approach in Tier 1/2 is the honest substitute).

## Why this ordering

Tier 1 is deliberately "everything that's pure math on data you already have" — it's the highest ratio of interview-demonstrable sophistication to actual new engineering, since none of it needs new API budget, new connectors, or new data-model changes beyond what the Excel import already added. Tier 2 costs a small, known amount of API budget per ticker and is worth doing once Tier 1 is solid. Tier 3 either needs money (real ESG/factor data), a genuinely new data model (transaction history for wash-sale detection), or overlaps with the already-scoped Bonds & Derivatives plan — good to know about, not worth starting yet.
